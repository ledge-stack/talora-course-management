## Executive Summary

The entire Talora repository was restructured from a basic two-folder Express/Next.js project into a **production-aligned API-first modular monorepo** driven by the System Architecture Document (SAD) and Product Requirements Document (PRD). GitHub Issues, CI/CD pipelines, and repository documentation were overhauled to give developers a complete, sequential, and validated implementation roadmap.

## 5. CI/CD Workflow Overhaul

**File:** [.github/workflows/ci.yml](file:///d:/Talora/.github/workflows/ci.yml)

### Job Architecture

```
PR Push
  │
  ├── typecheck     (tsc --noEmit, all packages)
  ├── lint          (eslint apps/* packages/*)
  ├── unit-tests    (jest, packages/domain + all workspaces)
  ├── validate-db-schema  (Postgres service container + prisma migrate deploy)
  │
  └── [after all 4 pass] build  (npm run build --workspaces)
  │
  └── [PRs only] pr-checks  (conventional commit title validation)
```

### Key Improvements Over Previous CI

| Old CI | New CI |
|--------|--------|
| Single sequential job | 5 parallel jobs + 1 gated build |
| No TypeScript type checking | `tsc --noEmit` on every package |
| No DB validation | Postgres service container + real migration run |
| No PR title enforcement | Conventional commits required |
| No concurrency cancellation | Stale runs cancelled on new push |
| Lint ran after build | Lint runs in parallel, independently |

## 9. Decisions & Rationale

| Decision | Rationale |
|----------|-----------|
| Modular monorepo over microservices | Maintains transactional integrity for group memberships without distributed system cost |
| Domain package with zero dependencies | Pure validators are independently testable and portable to mobile client |
| OpenAPI contracts as Phase 1 item | Frontend and mobile can develop against the spec in parallel with backend |
| DB schema validation in CI (real Postgres) | Catches migration failures before they reach any environment |
| Observability wired at Phase 2 (not 6) | Audit logs for auth events have no value if added retroactively |
| Conventional commit enforcement on PRs | Enables automated changelog generation and semantic versioning |
| Leadership transfer as separate issue | Atomic RBAC role change is a distinct, high-risk transactional operation |
| Notification outbox before announcements | Zero-loss delivery guarantee must exist before any notification-emitting feature |
